目录分别做什么

目录用途说明
wm/软件本身app.py 是桌面入口；batches.py 负责队列；masks.py 定位；repair.py / lama.py 修复；pipeline.py 串联与输出。
tests/程序行为检查覆盖选区边界、PDF、修复路由、导出、界面和回归管控；不能代替实际图片验收。
tools/测试、维护、研究和报告脚本下表按用途列出；没有删除、移动或擅自接入默认应用。
config/固定门槛与范围规则regression_control.json、regression_tiers.json、regression_retirements.json；整理说明不改变规则。
data/输入、原始来源与评分参考图片输入与干净参考分开；参考只能在推理后评分时使用。
out/运行产物与历史证据每轮新目录，封存结果原位保留。
proposal/方案材料与可维护源文件有多轮 Word / PPT 产物，目前未纳入 Git；通过报告总目录进入。
.regression-control/本机观察基线指针本机状态，不进 Git；跨机不能直接照搬绝对路径。

平时使用哪些入口

./start.sh setup                 # 首次准备本地环境
./start.sh gui                   # 打开桌面程序
./start.sh check-data            # 校验固定数据，不运行模型
./start.sh test --plan           # 预览实际修改需要的检查
./start.sh test                  # 日常按影响检查
./start.sh test-release          # 完整三模式对照
.venv/bin/python tools/organize_project_docs.py  # 更新当前说明
.venv/bin/python tools/organize_project_docs.py --check  # 只核对说明和链接
.venv/bin/python tools/build_report_index.py    # 更新报告目录

已有本机观察基线，日常不要重新执行 freeze-baseline 替换比较依据。需要完整发布证据时走原放行流程。

Git 和本机备份

程序、测试、维护脚本、README 和已跟踪的文档通过 Git 保存。本轮新增的当前说明允许进入 Git，但本轮不自动提交或推送。

data/、大部分 out/、模型缓存及本机基线指针采用单独资源包或本机备份；部分报告虽在忽略目录内，仍已被 Git 跟踪，不能只看 .gitignore 判断。proposal/、可选修图配置和根目录临时图表文件夹尚未进入 Git。

换电脑时要另外保存：当前数据与来源、模型、完整封存基线及其资源、尚未入库的方案材料。可选修图配置可能包含密钥，保留在本机，不直接加入仓库。Git 精确状态见本轮整理记录。
