项目现状与后续开发说明

PDF 的部分类型已有改善，基础图片去水印仍未达到可用水平。下一步应保留有效分支，重点验证更适合照片的去水印方法。

02　分为多少类，每类现在用什么算法

12 类验收场景，细分为 22 种图片样式、11 种 PDF 结构，另有干净对照。场景可以重叠：同一个白色平铺水印也可能存在于扫描 PDF 中。这里的“类别”是测试范围；代码由多个共用分支处理，不能理解成已经完成了 33 套算法。

03　技术路线是否合适

PDF 独立对象：保留

能确认水印是独立文字或图片绘制时，直接省略该绘制，优先保留底层内容。

白底文档：继续完善

纸色、文字色与重复结构有用；可测出透明叠加时优先还原，保护正文、数字和表格线。

照片：调整主力方法

改为验证专门针对可见水印的模型；现有 OCR 和局部补图作为对照或局部辅助。

为什么当前照片路线效果差

  1. 很多位置根本找不到。本轮 42 张正例中，26 张走到 nonpaper_background。现有规则偏向白底页、特定方向的大字或重复图案。
  2. 找到了也不一定还原得好。LaMa 根据周围内容补画，容易抹平细纹理；透明水印下面仍有的信息，未被充分利用。LaMa 的官方定位是图像补全，见 官方项目。
  3. 放宽规则会误删正常内容。此前出现表格标签、页脚线和图表误改；这一轮已补保护，不能通过扩大擦除范围换取表面干净。
  4. 评分也需要完善。wm/verdict.py 的文字指标是二值笔画近似判断，并非真正读出文字；照片应额外检查纹理、主体和真实水印外区域。

候选模型先比较，再确定

方法为什么比较当前结论
WDNet ↗预测水印颜色、透明度和位置，尝试分离底图；与透明水印保留细节的目标相关。候选，尚无当前固定集实测，不能预先判为有效。
SLBR ↗联合水印定位与背景恢复；已有本地权重，可作为研究对照。旧 57 例实验中 52 例区域误差下降，但 56 份干净对照发生像素改动；不是可直接上线的方案。官方训练尺度为 256×256，高清适配需验证。
MNet ↗2025 年多尺度可见水印模型，官方提供代码和权重入口，可作为另一种专用方法。候选，下载可用性、运行兼容与本地效果仍需实测。
LaMa（当前） ↗保留为限定范围的补图基线，比较细节与边缘表现。现有定位和修复组合不足以完成基础照片任务。

透明水印优先尝试把叠加的颜色与底图分开；大面积不透明遮挡只能补出合理内容，不能保证原始细节，尤其不能凭补图结果认定被遮数字或文字已真实恢复。能否达到当前业务要求，必须由我们的样本和原尺寸输出确认。

实现层面必须知道的几个缺口
  • wm/masks.py 尝试导入 dark_text，但当前没有 wm/dark_text.py；导入失败会跳过。不能把这个入口算作已完成的深色文字算法。
  • wm/directional.py 是实验方向滤波代码，目前未接入主检测流程。
  • PDF 结构修改后的字节暂存在内存，PageResult 返回的是渲染页图；常规 write_results 导出 PNG 与 JSON。目前没有完整的原生 PDF 保结构导出链。“页图变干净”不能宣称文字可搜索、链接与批注均保留。
  • wm/structure.py 的旧 strip_pdf 仍有按资源删除图片的实现，当前主流程改走 process_text_page 与具体绘制删除；后续不要误接回旧全局删除路径。
  • 同页只要结构分支返回结果，主流程就直接使用它；复杂混合页尚未形成完整的“结构删除后再识别剩余像素水印”流程。
  • 新增照片文字分支只在限定条件下进入；photo_overlay.py 仅对可拟合的颜色关系细化，不是通用照片还原模型。

06　下一轮应该怎么改

先做一轮能决定技术路线的对比，选出有效方法后再接入产品。当前优先级是基础照片去水印，继续扩大类别和制作边缘样本不是前置条件。

  1. 保存当前基线，固定输入和规则。

    运行新固定集的 core 与 real，分别保存结果；同时保留历史 88 项回归。记录原尺寸输出、耗时、预测位置、代码与输入哈希。真实来源扩展只作为开发检查。

  2. 比较专门去水印模型与现有方法。

    在可复现环境中先试 WDNet 与 SLBR，再视可用权重加入 MNet；核实来源、代码／权重使用条件、离线运行和原尺寸处理方式。候选名单不是最终选型。

    做两类实验：一类给准位置，判断修复能否保留细节；另一类只输入带水印图片，检查自动找位置和完整效果。部分模型本身联合检测与修复，应按官方输入方式运行，不能随意改接口后把失败归给模型。

  3. 优先解决四种基础照片问题。

    局部文字、居中深字、居中白字、平铺文字。透明水印优先保留底下仍可见的信息；补画范围需受可信水印位置约束。若现成模型未达标，再用已有严格配对与干净负例做小规模适配训练，3 组近似配对按有效区域和低权重使用。

  4. 将“去干净”与“不损坏”一起验收。

    逐张检查水印残留、主体／纹理损伤、正常文字与 Logo 误删；文档核对关键数字和表格线。保留旧评分以观察回归，补充真实 OCR 字符检查与基于真值的区域外变化；不能通过放宽阈值制造提升。

    20 份历史干净对照继续保持原样，新负例单独报告；结果需在多个底图来源上改善。未达到质量条件的模型继续作为实验，不能直接替换默认处理。

  5. 保留有效 PDF 分支，补对象处理与导出。

    中文、独立文字与透明图片的已有改善不能回退。按绘制实例处理共享资源，再逐步补嵌套对象、路径、图章与图层；为混合页建立删除后复查；增加原生 PDF 保存并检查可搜索文字、链接、批注和页数。

  6. 输出易读报告，再决定是否扩大训练。

    固定输入前后对照、按类别通过情况、失败图、干净样本损伤、端到端耗时；竞品输出有证据才计入比较。确认候选在质量和误删上可用后，再优化速度并在目标 NVIDIA 工作站验证；当前 A6000 尚无可采信实测结果。

本轮应得到的决策：保留哪个候选、哪些样式已改善、哪些需要训练、哪些方法应停止投入。没有效果证据时，不承诺“换模型就能达到网站水平”。
